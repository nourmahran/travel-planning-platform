Prompt:
A user whose preferred currency is CAD is silently served the
itinerary currency, and an explicit ?currency=CAD is rejected,
even though the platform declares SUPPORTED_CURRENCIES. Treat
that list as the truth for validation, keep countries.currency
only for per-country defaults, and make a currency with no rate
fail loudly instead of quietly falling back.

How the output was used:
displayCurrencies is now the union of the distinct
countries.currency values and the codes declared in
SUPPORTED_CURRENCIES (trimmed, uppercased, 3 letters), so the
budget summary, the conversion route and entry validation all
accept one list. With SUPPORTED_CURRENCIES unset the union
collapses to the previous behaviour, and per-country defaults
still read countries.currency only. A budget entry or transport
cost is written without an FX lookup; the read path answers 400
"rate missing for <code> (<entry type> <id>, ...)" naming what
needs a rate, rather than returning a quietly wrong total.

Run the live Swagger pass against the shared team database
instead of a local one. Harden the harness before it touches
anything: one scratch database it cannot be talked out of, a

sessions. The itinerary is created on today + 3 and the flight
date is read from the database and applied by PATCH, so the run
does not go stale. Skips carry their reason, and one finally
